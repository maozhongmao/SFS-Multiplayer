# 版本计划

> 定于 2026-10-15。改动版本号前先看这里。

## 当前版本：`V1.4`（**已完成，尚未发布**）

包含：联机作弊开关（服务端配置驱动 + 单项拦截）、服务端 JSON 配置文件、日志分类与彩色输出、
以及本轮修掉的联机问题（作弊入口缺失 / 开关点了不刷新 / 1.5 包编译失败）。

- csproj：`<Version>1.4</Version>`，`AssemblyName = SFS-Multiplayer-1.6-V1.4` / `SFS-Multiplayer-1.5-V1.4`
- 产物目录：`artifacts/release-V1.4/`（7 个资产 + `SHA256SUMS.txt`）
- **发布时机：用户决定放在 JS 插件做完之后一起发**（在此之前不动发布标签）。

## 之后怎么编号

| 版本 | 用途 |
|---|---|
| `1.4.1` | 1.4 之后、插件之前的任何改动（已排队的：P2P 停止中继、P2P 校验上行、全局作弊模式等）|
| `1.4.2` | **JS 插件开始动工时使用这个版本号**（用户指定）|
| 发布标签 | 发布发生在 JS 插件完成之后；标签沿用三段式写法（如 `V1.4`），由用户最终确认 |

## 每次发布前的固定动作

1. `build-release.ps1 -Version <版本>` → 产出 7 个资产 + 校验和（脚本自带瘦身参数 ✓）
2. 客户端装进 Mods 自测：**入口出现 → 开关能亮/灭 → 被禁项点不动**
3. 更新 `CHANGELOG.md` 与 `RELEASE-NOTES-<版本>.md`：
   **只写有证据的根因，不写推测**；发出去的版本必须与实测过的构建哈希一致
4. 服务端上板并核对 `cheats: enabled=... flags=0x....` 启动行

## 已知的编号约定（沿用）

- 新功能：第三段 +1；修 bug：第四段 +1（`1.4` → `1.4.1` → `1.4.2`）
- 消息号（PacketType）**永不改**；停用的功能保留号位并注明原因
