## 版本规则

- 前两段锁定 `2.1`。
- 新功能：第三段 +1，第四段归零（例：2.1.2.1 → 2.1.3.0）。
- 纯 bug 修复：第四段 +1。
- 一批功能只打一次包、只升一次版本；批内回归才升第四段。

- **2.1.0.2**：已验证可启动基线 `android/patchapp/build/test/authority-hard-sync-2.1.0.2.apk`，versionCode 938，targetSdk 33。DEX/native 必须以此包为基准。

  - `g_known_part_fp/id/ptr`、`read_part_ptrs()`、`find_part_owner()`。

- **2.1.3.0**：确定性 PartId（versionCode 948）
  - 上行 CreateRocket 的 part id、joints、stages 全部改成 PC 同款 `DeterministicPartID`（FNV + 位置）。
  - DestroyPart 使用同一个确定性 ID。

- **2.1.3.2**：本地火箭对象变化时不再 Destroy/Create，改为同一 gid 重新上传结构覆盖（versionCode 950）。
- **2.1.3.3**：修复远端 Location 悬挂指针崩溃（versionCode 951）
  - 写 Location 前校验对象类型；stale Location 直接跳槽，不再调用 `set_Value`。
- **2.1.3.4**：处理收到的 type10 DestroyRocket（versionCode 952）
  - 之前 Android 完全不处理 type10，PC 清掉的平台火箭在手机上仍是幽灵，碰撞体还在。
  - 现在收到后清远端缓存、标 dirty，主线程销毁 Unity 火箭并停止重生。
- **2.1.3.5**：发射台清理（versionCode 953）
  - 进入世界/换箭/发射时扫描发射台 50m 内远端火箭，发 DestroyRocket；服务端会拒绝正在被玩家控制的。
  - 新增 `clear_remote_pad_rockets()`、`mp_queue_destroy_rocket()`、发射台坐标记录。
- **2.1.3.6**：移除 `rr_check_alive` 的列表误判（versionCode 954）
  - 旧逻辑“Rocket 列表里找不到就清槽”在火箭多时会批量误清，造成 6 秒消失后重生。
  - 只保留对象类型校验。消失时间从约 6 秒缩短到约 1 秒。
- **2.1.3.7**：发射台周期清理（versionCode 955，当前安装）
  - 世界中每 120 帧持续清理发射台 50m 内远端无主火箭，不再等新火箭出现。
  - 当前仍存在约 1 秒远端火箭消失（PC 端重建），用户暂时搁置。

## 2.1.4.0–2.1.5.0 追加（2026-11-08 Batch A）

- **2.1.4.0/4.1/4.2（versionCode 956–958）**：尝试移植 PC 发射台碰撞隔离。
  - 解析到 `UnityEngine.Physics2DModule` 的 `Collider2D`/`Physics2D`，但 IL2CPP 把 `Physics2D.IgnoreCollision` 方法裁掉了，反射始终为 NULL。
  - 结论：Android 无法用该方式做碰撞隔离；**不计入功能**。代码保留但空转。
- **2.1.5.0（versionCode 959，当前安装）**：协议层 + 模块写回。
  - type6 `UpdateWorldTime`：接收服务器世界时间。
  - type12 `UpdateRocketSecondary`：接收油门/RCS/转向/输入并缓存。
  - type15 `EngineModule`：`engine_on` 写回远端零件变量。
  - type16 `WheelModule`：`wheel_on` 写回。
  - type17 `BoosterModule`：`booster_primed` + `fuel_percent` 写回。
  - type18 `ParachuteModule`：`animation_state` + `deploy_state` 写回。
  - type19 `MoveModule`：`state` + `state_target` 写回。
  - type20 `ResourceModule`：资源百分比写回。
  - type27 `RenameRocket`：接收并写回远端名字（但 PC 发送的 `rocketName` 为空，实际改名未生效，暂时搁置）。
  - type28 `UpdatePartTemperature`：接收并缓存零件温度。
  - type2/3 `PlayerConnected/Disconnected`：解析恢复正确（之前整体错 1 字节，id 是垃圾值）。
  - 关键修复：这些新包的业务字段起点是 **f+14**（ptype 在 f+13），之前 11 处误用 f+13，已统一修正。
  - 模块写回方式：更新 `mp_rrocket_t.parts[].tv/nv` 后置 `dirty=1`，由远端重建应用；因此切换引擎/轮子/降落伞时可能有一次约 1 秒重建。
- **PC 端改名发送**：新增 `PollLocalRocketRenames()`，轮询控制中火箭的 `rocketName`，变化时发 `Packet_RenameRocket`。
  - 实测发送值为空字符串，PC 游戏里改名似乎不写 `rocketName`，按用户要求搁置。
- **PC DLL 当前 SHA-256**：`CA7CB8490700ABC150A700F64B963C5B6053922BB35ED9BEE1DA996977ED9CC8`（2026-11-08 18:12）。

- 删除能力位检查：不再要求 readRocket / writeRocket / sendMessage / log / admin 能力位。

### 插件 API 扩展
- 元数据：`sfs.plugin` -> id/name/author/version/minServerVersion。
- 生命周期：`onLoad()`、`onUnload()`、`onTick()`（每秒一次，与事件同节拍）。
- 文件 API：
  - `sfs.readFile(path)`
  - `sfs.writeFile(path, text)`
  - `sfs.listDir(path)`
  - `sfs.deleteFile(path)`
  - `sfs.mkdir(path)`
  - `sfs.exists(path)`
  - `sfs.renameFile(from, to)`
- 交互 API：`sfs.askUser(question)`。
- 现有 API：log/sendMessage/broadcast/players/getWorldTime/serverInfo/kick/clearDebris/setTimeScale/readRocket/writeRocket。
- 仍缺（对比同行）：原始包级钩子、面板回传、自定义消息拦截、整枚火箭完整状态写入。
- 已删除未使用插件引擎：`Server/cpp/src/plugins/demo/`。
- `plugin_host.cpp` / `plugin_app.cpp` 单独用 zig 编译通过。

### 服务端体积
- 删除 demo/移除沙箱**没有改变**服务端二进制体积，因为 `build.sh` 没有把 `src/plugins/*` 编进服务端。
- 当前 `build/verify-out/SFS-Multiplayer-Server-linux-armv7` 仍为 716,240 字节（699.5 KiB）。
- 结论：插件引擎未接生产构建；要启用插件 API 需把插件源码加入构建，体积会变大。用户已确认暂时不管体积。
