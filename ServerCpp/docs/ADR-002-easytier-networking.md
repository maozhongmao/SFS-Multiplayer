# ADR-002：以命令行方式调用 EasyTier 实现玩家间异地组网

- **状态**：已决定，未实施
- **优先级**：**次要任务**（低于 ADR-001 的传输层 KCP 改造）
- **影响范围**：仅涉及客户端使用方式与配套工具，**不改动服务端协议，不改动现有客户端代码**
- **相关**：ADR-001（传输层 KCP）—— 两者独立，见文末

## 决策

通过**命令行调用 EasyTier**（外部进程，非库集成）实现玩家之间的异地组网联机，
使异地玩家能像在同一个物理局域网内一样互相联机。

**服务端架构不变**：仍然是传统的中心化 / 半中心化（服务端权威 + 撮合），
EasyTier 不参与服务端职责，也不改变服务端与客户端之间的任何协议。

## 定位：它解决的是"局域网联机（房主模式）"的异地问题

用 Minecraft 的两种联机方式对齐：

| 模式 | 拓扑 | 谁需要 EasyTier |
|---|---|---|
| **服务器联机** | 玩家 A/B/C → 独立服务器 | **不需要**（服务端有公网地址即可） |
| **局域网联机** | 玩家 B/C/D → 玩家 A 开的世界（房主） | **需要** —— 异地玩家本来互相不可达，EasyTier 把他们拉进同一个虚拟局域网 |

所以 EasyTier **装在玩家侧**（房主和朋友各自的机器上），跑在游戏之外，
服务端完全不参与。房主开的世界对异地朋友来说"就跟在隔壁一样"能直接连上，
**不需要公网 IP，也不需要端口转发**。

## 查证过的事实（实施前不必重新调研）

**版本与来源**：官方仓库 `EasyTier/EasyTier`，当前 `v2.6.4`，Rust + Tokio 实现。

**平台覆盖（官方发布物齐全，含我们需要的全部目标）**：

| 目标 | 发布物 |
|---|---|
| **Luckfox Lume 板子（ARMv7）** | `easytier-linux-armv7-v2.6.4.zip`（另有 armhf / armv7hf 变体） |
| **PC 玩家（Windows）** | `easytier-windows-x86_64-v2.6.4.zip`（另有 i686 / arm64） |
| 其他 Linux | aarch64 / loongarch64 / mips / mipsel / riscv64 |
| macOS | x86_64 / aarch64 |
| 安卓 | `app-arm-release.apk` / `app-arm64-release.apk` |

**体积**（决定板子上放哪里）：

| 发布物 | zip 体积 |
|---|---|
| `easytier-linux-armv7` | **19.0 MB** |
| `easytier-windows-x86_64` | **29.5 MB** |
| `easytier-linux-aarch64` | 19.3 MB |

> 解压后的二进制体积需实测（Rust 静态链接通常显著大于 zip）。
> **注意板子约束**：`/mnt/UDISK` 当前仅 28.6 MB 可用空间，
> ARMv7 包放 UDISK 可能吃紧，必要时放 TF 卡（`/mnt/mmc`）。

**命令行接口**：

- `easytier-core` —— 主程序（启动组网）
- `easytier-cli` —— 状态查询：`easytier-cli peer` / `route` / `node`

关键参数（每个参数都有对应的 `ET_*` 环境变量形式）：

| 参数 | 用途 |
|---|---|
| `--network-name` / `--network-secret` | 网络标识与密钥，**同网络所有节点必须一致** |
| `-p, --peers` | 初始要连接的对等节点（如 `udp://1.2.3.4:11010`） |
| `-e, --external-node` | 使用公共共享节点来**发现**对等节点（无需公网 IP） |
| `-i, --ipv4` / `-d, --dhcp` | 指定虚拟 IP / 自动分配（默认从 `10.0.0.1` 起） |
| `-m, --instance-name` | 同机多实例区分 |
| `-r, --rpc-portal` | RPC 管理端口（结构化查询状态，比解析 CLI 文本可靠） |
| `--config-file` | 改用 TOML 配置文件（命令行参数会覆盖文件中的值） |

**默认监听端口**：TCP 11010、UDP 11010、WebSocket 11011、WebSocket SSL 11012、WireGuard 11013。
**与游戏端口 9806 不冲突**。

**连通性**：节点自动尝试 NAT 穿透建立 P2P；穿透失败时经**公共共享节点中继**。

## 实施设计要点

1. **密钥必须走环境变量，不要走命令行参数。**
   命令行参数会出现在进程列表（`ps`）里，任何本机用户都能看到网络密钥。
   所有参数都有 `ET_*` 环境变量形式（如 `ET_NETWORK_SECRET`），用环境变量传递。

2. **状态查询优先走 RPC，其次才解析 CLI 文本。**
   `easytier-cli peer` 的输出是给人看的，解析它会在版本升级时碎掉；
   `-r/--rpc-portal` 提供结构化管理接口。

3. **进程由我们的工具托管**：启动、停止、健康检查、异常重启。
   以外部进程方式调用意味着它崩了不会拖垮游戏，但必须有人看住它。

4. **游戏侧零代码改动。**
   玩家在虚拟局域网里把服务端地址填成 EasyTier 分配的虚拟 IP
   （如 `10.0.0.2:9806`）即可，客户端登录页本来就支持手填 `IP:Port`。
   这也是本任务能作为"次要任务"独立推进的原因 —— 它不阻塞主线。

## 组网方式：直接用社区免费公共节点

**决定：使用 EasyTier 社区提供的免费公共共享节点，不自建。**

公共节点实际承担两件事：

1. **发现**（常规路径）：帮你找到同一网络内的其他节点，交换各自的地址。
2. **中继**（仅当 P2P 打洞失败）：两个节点直连打不通时，数据才经公共节点转发。

**关键点：NAT 穿透成功时，玩家之间的流量是直连的，不经过公共节点。**
公共节点的角色更像"交换地址的介绍人"，而不是流量中转站 —— 所以用免费公共节点
不等于把游戏流量交给第三方。只有穿透失败的网络环境（严格 NAT / 对称 NAT）
才会走到中继那一步，那时才有额外延迟的代价。

自建共享节点**不做**（将来若确实需要再说，一台有公网 IP 的机器即可跑）。

## 其余约束

- **板子空间**：见上文 `/mnt/UDISK` 的 28.6 MB 约束。
- **防火墙**：穿透失败常因防火墙拦截入站，需要在玩家侧放行 11010（或依赖中继兜底）。

## 与服务器撮合 P2P 的区别（两套东西，不要混）

EasyTier 组网与「服务端撮合的 P2P 直连」是**两套独立的机制**，传输的数据也不同：

| | EasyTier 组网 | 服务端撮合的 P2P |
|---|---|---|
| 层次 | **网络层**（虚拟局域网，搬原始数据包） | **应用层**（跑本项目自己的 Hello/Ack/State 协议） |
| 谁参与 | 只在玩家侧，服务端完全不参与 | 服务端负责撮合（`P2PPeerOffer`），玩家间直连传输 |
| 解决什么 | 主用场景是**房主模式**：异地朋友连不上房主时打通链路 | 主用场景是**服务器模式**：玩家间状态流不绕服务器 |
| 是否认游戏协议 | 不认（对上层透明） | 认（就是本项目的协议） |
| 与 ADR-001 的关系 | 无关，在 KCP 更下面一层 | **需要一起 KCP 化**：客户端要跑两条链路（连服务器、连 P2P peer） |

**EasyTier 不替代我们自己的 P2P**，它只负责把链路变得可达。

## 与 ADR-001（KCP）的关系

| | ADR-001 KCP | ADR-002 EasyTier |
|---|---|---|
| 解决什么 | **传输质量**：连上之后的延迟与丢包 | **可达性**：异地的两个人怎么"看见"对方 |
| 在哪里 | 游戏协议内部（服务端 + 客户端 mod） | 游戏之外（玩家侧独立进程） |
| 是否改协议 | 是（线格式整体更换） | **否**（零协议改动） |
| 依赖关系 | 独立 | 独立 |

**两者独立，可以分别推进。** 唯一的相关性：EasyTier 让链路变成真实的公网链路后，
ADR-001 里 KCP 相对 TCP 的优势才会真正体现（当前的局域网延迟下测不出来）。
