# 已知问题与注意事项

> 本篇记录**已发布版本**的已知限制、使用注意事项与反馈方式。发现与当前版本不符的内容，请以实际行为为准并联系我们。

## 设计上的限制（属预期，不是缺陷）

| 限制 | 说明 |
| --- | --- |
| 客户端与服务端必须同版本 | 协议与状态结构随版本演进，混用会导致握手失败或行为异常 |
| 仅支持 Spaceflight Simulator 1.6 | 模组依赖 1.6 的装配与 API，其他版本不保证可用 |
| 需要 `UITools` 前置模组 | 客户端界面依赖它提供的组件，缺失会导致界面异常 |
| 玩家直连依赖 UDP 互通 | 双方网络阻断 UDP 时不会启用直连，自动回退到服务端中转（仍可联机，延迟更高） |
| 物理并不是逐帧完全一致 | 不同机型、帧率、加载顺序下，同一枚火箭的细微运动可能有偏差；这是插值与网络同步的固有取舍 |
| 人数与对象规模受服务端性能限制 | 玩家数、火箭数与部件数越多，服务端 CPU/带宽压力越大；低配置设备应下调人数上限 |
| 太空垃圾会自动清理 | 失去控制且部件数低于阈值的碎片会被移除，这是刻意行为；阈值可配置 |

## 使用注意事项

- **`Mods` 目录只保留一份**本模组 DLL：两份同时存在会导致重复补丁与异常行为；
- **同一端口只运行一个服务端实例**：重复启动会出现两个进程争抢收包，表现为"时好时坏、莫名其妙的不同步"；
- **升级前备份状态存档**：虽然存档采用原子写入并提供 `.bak` 回退，但跨大版本的存档结构可能不兼容；
- **不要公开分享**服务端口令、实验性功能口令与真实服务器地址；
- 面向公网提供服务时，注意放行 **TCP 与 UDP** 两种端口。

## 排障速查

| 现象 | 首先检查 |
| --- | --- |
| 连不上 | 端口是否放行（TCP+UDP）、版本是否一致、是否有残留进程占用端口 |
| 握手失败 | 双方版本、密码、人数上限、重名 |
| 进服后不同步 | 客户端日志 → 服务端日志 → 网络是否阻断 UDP |
| 位置跳变 | 是否启用了直连；未启用时链路质量如何 |
| 发射后迟迟不出现 | 先等加载流程结束；仍不出现则看两端日志的创建记录 |
| 服务端反复退出 | 日志末尾原因：端口占用 / 配置字段非法 / 存档损坏（用 `.bak` 回退） |
