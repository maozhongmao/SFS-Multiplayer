# 部署与运维

> 本篇示例中的地址、端口与路径均为占位符。真实部署信息（域名、端口分配、凭据）请由服主自行保管，不要写入仓库或公开文档。

## 一次最小部署

1. 选择与机器架构匹配的服务端文件（Windows x64 / ARM64，Linux x86-64 / ARM64 / ARMv7）；
2. 把**可执行文件**与**同目录的 `server.yml`** 放在一起；
3. Linux 需要先赋予执行权限（`chmod +x`），再直接运行；Windows 直接双击或命令行运行；
4. 确认监听端口在路由器/防火墙/云安全组上放行（**TCP 与 UDP 都要放行**，见下）；
5. 让玩家用与本次服务端**同版本**的客户端模组加入。

## 配置：`server.yml`

服务端配置与可执行文件同目录，使用 **YAML** 格式。仓库中提供了 `Server/server.example.yml` 作为示例（内容与服务端内置的默认模板一致），照它修改即可：

| 类别 | 典型内容 |
| --- | --- |
| 基础 | `bind_address`（监听地址）、`port`（监听端口）、`max_connections`（人数上限） |
| 状态 | `world_path`（留空则新建空世界）、`state_path`（存档路径）、`auto_save_seconds`（自动保存间隔） |
| 玩家 | `password`（留空表示无密码，也可用环境变量 `SFS_SERVER_PASSWORD`）、`block_duplicate_player_names` |
| 网络与聊天 | `update_rockets_period`、`chat_message_cooldown`、`max_username_length`、`max_chat_message_length`、`debug` |
| 实验性功能 | `experimental_access.passphrase`（留空即关闭服务端侧解锁） |
| 玩家直连（P2P） | `p2p.enabled`、`proximity_meters`、`validation_interval_seconds`、`peer_timeout_seconds`、`transition_buffer_seconds`、`max_group_members`、`max_direct_peers_per_client` |

改完配置需要重启服务端生效。IPv6 地址在 YAML 中必须加引号（`"::"` / `"::1"`），因为 `:` 在 YAML 里有语法含义。

## 网络要求

- 服务端需要放行的端口：**TCP 与 UDP 都要**（高频状态走 UDP，业务包走可靠通道）；
- 玩家直连（P2P）：**双方 UDP 互通**时才会启用；NAT 严格、UDP 被阻断时不会启用，此时自动回退到**服务端中转**，游戏仍可正常联机（延迟略高）；
- 若玩家普遍无法启用直连，先确认双方所在网络是否阻断 UDP，而不是调服务器参数。

## 状态存档

- 世界状态以 **JSON** 形式保存，采用**原子写入**并提供 `.bak` 回退，异常中断不会把存档写坏；
- 「重新开一个干净世界」：停止服务端 → 把状态文件移走（不要直接删，留作备份）→ 启动服务端；
- 想回到上一份状态：用 `.bak` 覆盖当前文件后重启。

## 日志与观测

| 现象 | 看什么 | 常见原因 |
| --- | --- | --- |
| 玩家连不上 | 服务端日志有无握手记录；客户端 Multiplayer 菜单的提示 | 端口未放行 / TCP-UDP 不匹配 / 版本不一致 |
| 握手失败 | 服务端日志的拒绝原因 | 客户端与服务端版本不同、密码错误、人数已满、重名 |
| 能进但不同步 | 服务端日志有无状态包转发；UDP 是否被阻断 | 链路只通了可靠通道、UDP 被防火墙丢弃 |
| 位置跳变明显 | 网络延迟与丢包情况 | 直连未启用且中转链路质量差；先查网络再查参数 |
| 进程反复退出 | 服务端日志末尾 | 端口被占用、配置字段非法、存档损坏（可用 `.bak` 回退） |

排查顺序建议：**先看客户端日志 → 再看服务端日志 → 最后才怀疑参数**。

## 低配置设备（如开发板）注意事项

- **同一端口只能有一个服务端实例**：重复启动会产生两个进程争抢收包，表现为"时好时坏、莫名不同步"，先确认只有一个进程；
- 这类设备内存有限，建议：
  - 限制最大玩家数，关掉不需要的插件与实验性功能；
  - 定期把状态存档备份到别处；
  - 观察常驻内存与 CPU，出现持续涨高再考虑换设备或加虚拟内存；
- 长时间运行建议配合进程守护（开机自启 / 掉线拉起），并保留**唯一实例**约束。

## 升级与回退

- 升级：停服 → 备份状态文件与当前可执行文件 → 换上新版本可执行文件（与同版本 `server.yml`）→ 启动；
- 回退：换回旧可执行文件即可（旧版本文件请独立保留，不要覆盖）；
- 客户端模组与服务端**必须同版本**，升级时两者一起换。

## 安全建议

- 不要把服务端的**口令、实验性功能口令**写进公开文档或截图；
- 面向公网时，建议只暴露必要端口，并定期更新服务端版本；
- 发现安全问题时请按 [`SECURITY.md`](https://github.com/maozhongmao/Spaceflight-simulator-Multiplayer/blob/main/SECURITY.md) 通过联系邮箱报告，不要在公开 issue 中贴出可利用细节。
