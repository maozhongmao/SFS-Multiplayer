## 一、已完成，尚未上传

以下内容已在开发分支上完成并通过本机验证，**尚未上传到本仓库与发布页**：

| 项 | 状态 | 说明 |
| --- | --- | --- |
| **KCP 传输重构** | ✅ 已完成，未上传 | 传输层从"TCP + UDP 双通道"改为 **KCP（基于 UDP 的可靠传输）**：把可靠送达与低延迟统一到一条通道上，减少双通道分流与切换带来的边界问题（首次连接偶发失败、状态与业务包不同步等）。设计决策见 ADR-001 |
| **性能优化** | ✅ 已完成，未上传 | 客户端侧：远方火箭的爆炸特效按帧限流（自己的火箭爆炸不卡，别人的爆炸不再拖垮帧率）、发射/加载界面兜底关闭（不再出现"卡在加载屏、火箭像没造出来"）、已存在的火箭不再被反复重建、行星地形查询异常保护；服务端侧：同一火箭的状态只保留最新一条，慢客户端不再积压过期状态 |
| **C++ 低占用服务端** | ✅ 已完成，未上传 | 面向低内存设备重写的服务端（几十 MB 内存可长期运行），与现有客户端使用同一套线格式，进程常驻只需极小内存 |
| **开发板 24 小时长跑验证** | 🔄 进行中 | 在低资源设备上做长时间稳定性验证（内存与 CPU 曲线、日志无异常），结论达标后再上传 |
| 文档补充 | 🔄 部分完成 | 已建立本维基（结构、架构、协议、部署、验收、约定）；KCP 时代的线格式与部署说明随后补充 |

## 二、接下来要做

> 设计决策按 ADR（Architecture Decision Record）归档：**ADR-001 传输层 KCP 改造**（已实施，见上表）、**ADR-002 EasyTier 异地组网**、**ADR-003 Proxy Protocol 与命令系统**；ADR-002 / ADR-003 的正文随对应实现一并公开。

| 项 | 说明 |
| --- | --- |
| **EasyTier 异地组网（ADR-002）** | **已决定，未实施**：通过命令行调用 EasyTier（外部进程，非库集成），让异地玩家像在同一局域网内一样直接联机（房主开世界、朋友直连）。装在玩家侧、跑在游戏之外，**不改动服务端协议、不改动现有客户端代码**，服务端仍是中心化权威 + 撮合 |
| **Proxy Protocol 与命令系统（ADR-003）** | **待实施**：为「负载均衡 / 反向代理 / 内网穿透后端」场景解析 **PROXY Protocol V2（UDP）**头，还原真实客户端 IP 与端口，用于访问控制、限流与日志；同时改进服务端命令系统 |
| 断线重连身份复用 | 短时间掉线后用原身份自动恢复，不再整段重新握手；服务端侧的重连宽限与状态保留已先行就位 |
| 控制权变更收尾 | 火箭分离 / 对接后控制权自动迁移到正确玩家，减少"无主火箭"与切权瞬间的位姿跳变 |
| 加载期竞态修复 | 世界加载阶段的偶发异常（重复创建、状态错位）继续收敛，目标是长时间游玩更稳 |
| 网络自适应调参 | 按实测链路质量调整插值上限与状态发送间隔，兼顾高延迟下的操作手感与画面平滑 |
| 多人压力测试 | 提高同时在线人数，观察服务端 CPU / 内存 / 带宽，给出各档机器的推荐人数配置 |
| 低配设备部署文档 | 面向开发板与小机器的部署建议：单实例约束、存档备份、内存与虚拟内存调优、开机自启 |
| 跨版本兼容 | 尽量保持旧版协议兼容；只有线格式真正不兼容时才提升协议版本，并用旧版客户端与服务端做交叉验证 |

## 三、平台支持现状

- **已发布**：Windows（x64 / ARM64）、Linux（x86-64 / ARM64 / ARMv7 32 位）；
- 各平台功能与协议完全一致，可以互相联机；
- 计划补充低内存设备（ARMv7、几十 MB 内存）的运行建议与验证数据。
