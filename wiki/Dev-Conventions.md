# 开发约定

> 本篇是参与本项目开发时的约定，目的是让代码长期可维护、发布可追溯、多人协作不踩坑。

## 许可证头

- 所有源码文件顶部保留 **MPL-2.0 Exhibit A** 的英文头注释（法律文本不翻译）：

```csharp
/*
  This Source Code Form is subject to the terms of the Mozilla Public
  License, v. 2.0. If a copy of the MPL was not distributed with this
  file, You can obtain one at https://mozilla.org/MPL/2.0/.
*/
```

- 新建文件同样要带；XML 声明（如 `.csproj`、`.xml`）必须位于文件最前，头注释放在其后。

## 文案语言

- **游戏内可见文案统一用英文/ASCII**：SFS 的中文字形不完整，中文会显示成方框；
- **运行/诊断日志可以用中文**，便于排查；
- 报错与提示尽量给出"发生了什么 + 该怎么办"，不要只抛异常信息。

## 命名与注释

- 命名只说清"这段代码干什么"，**不要起花哨名字**；
- 注释解释**意图与约束**（为什么必须这样写），不复述代码表面行为；
- 不使用未定义的常量或裸魔数：出现阈值、上限、间隔时要有名字与一句说明。

## 构建与依赖

- 模组**用 `dotnet build` 编译，不通过 Unity 编辑器构建** —— Unity 用于做游戏，不用来做模组；
- 目标框架与依赖以工程文件为准（客户端模组为 `net48`）；
- 服务端为**自包含单文件**发布，避免终端用户安装运行时；
- 分发时优先**单文件 / 内嵌依赖**，不要依赖外部文件路径（换目录就起不来是常见投诉源）。

## 版本号与发布

- **新增功能**：版本号第三段 +1；**修复缺陷**：版本号第四段 +1；
- 每个版本使用**独立目录与独立产物**，禁止覆盖既有版本，保证随时可回退；
- 发布使用**完整语义版本号**，Release 标题与说明、README 中出现的版本号必须一致；
- 发布产物**原样上传**（不重新打包、不改动二进制），并在发布页给出 SHA-256，发布后再次核对大小与哈希；
- 客户端模组与服务端**同版本发布**，在说明中明确"哪个模组配哪个服务端"。

## 协议与兼容

- 报文**编号一经使用不再改动**；新增功能使用新编号，尽量保持跨小版本线格式兼容；
- 新增独立消息优先复用既有报文体，只有线格式真正不兼容时才提升协议版本；
- 涉及协议改动时，用**旧版本客户端/服务端**做一次交叉连接验证。

## 修订既有行为

- 改动已有功能前先确认原设计意图；**不要因为"看起来更优雅"就替换掉正在工作的实现**；
- 删除或替换既有功能需在提交信息里说明原因与替代路径；
- 保留可回退能力：旧实现若被停用，标注清楚"已停用 + 保留原因"。

## 提交信息

- 使用前缀 + 中文简短的格式，例如：

```text
Feat: 新增玩家直连通道的撮合与回退
Fix: 修复发射后火箭偶发未创建的问题
```

## 文档

- **README 保持简洁**：只介绍项目用途、组成、功能与使用前提，**不塞版本更新日志**；
- 详细内容（架构、协议、部署、排障）写入本维基；
- 版本更新内容写进对应 Release 说明；
- 文档与代码不一致时，以代码为准，并及时修正文档。
