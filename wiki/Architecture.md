# 联机架构

> 本篇描述**已发布版本 V1.1.4** 的架构与行为；工程与文件的实际结构以仓库源码为准。

## 三句话概括

1. **客户端模组**跑在玩家的游戏进程里，负责采集本机玩家的火箭状态、上报服务端、并把外来状态应用到游戏对象上；
2. **独立服务端**是权威方：管理会话、维护世界状态、裁决控制权、分配状态更新权威；
3. **玩家直连（P2P）**在配对成功后让两名玩家之间直接传火箭状态，直连不可用时自动回退到服务端中转。

```text
玩家 A 游戏进程                     服务端进程                      玩家 B 游戏进程
┌───────────────┐                ┌───────────────┐               ┌───────────────┐
│ 客户端模组     │  握手/会话      │ 会话管理       │   握手/会话    │ 客户端模组     │
│ 状态采集/应用  │ ─────────────► │ 世界状态       │ ◄───────────── │ 状态采集/应用  │
│ 控制权请求     │ ◄───────────── │ 权威分配       │ ─────────────► │ 控制权请求     │
└───────┬───────┘   状态同步       └───────┬───────┘   状态同步      └───────┬───────┘
        │                                 │                                │
        └──────── 直连通道（P2P，配对后启用）───────────────────────────────┘
                 直连中断 → 自动回退到经服务端中转
```

## 客户端侧

客户端部分源码位于 `Client/`，按职责拆成几个工程：

| 工程 | 职责 |
| --- | --- |
| `MultiplayerSFS.Common` | 客户端与服务端共享的协议定义与数据结构（报文类型、序列化、状态结构） |
| `MultiplayerSFS.Mod` | 模组主体：会话管理、世界状态镜像、状态采集与上报、插值渲染、控制权协调 |
| `MultiplayerSFS.Mod.Patches` | 对游戏本体的补丁层：在合适的时机挂接发射、加载、世界事件等流程 |

主要概念：

- **会话**：与服务器的连接、握手、玩家身份与断线处理；
- **世界状态镜像**：本地保存"服务端认为的世界"，包括火箭、部件、阶段、控制权、世界时间；
- **状态采集与上报**：只上报本机玩家有权更新的对象，避免多人重复写同一枚火箭；
- **插值渲染**：把低频到达的状态平滑成连续运动（见下）；
- **控制权协调**：发起控制请求、等待服务端回执、切换时同步非权威状态。

## 服务端侧

服务端源码位于 `Server/`：

| 工程 | 职责 |
| --- | --- |
| `SfsMultiplayer.Protocol` | 与客户端共享的协议实现（报文编解码、线格式） |
| `SfsMultiplayer.Server` | 服务端主体：会话、世界、权威、配置、存档 |
| `SamplePatch` | 服务端插件（补丁）系统的示例工程 |

服务端不依赖游戏进程，不修改导入的 SFS 存档；状态以 JSON 形式原子保存，并提供 `.bak` 回退。

## 权威与控制权

- **权威分配**：服务端按玩家与火箭的关系决定"谁的状态更新算数"，**当前控制该火箭的玩家优先**；
- **控制权协调**：控制权变更统一由协调器处理，切换时同步非权威状态，减少位姿跳变；
- **分离解析**：火箭分离产生的新火箭，其控制权归属在分离时解析，避免出现无主火箭；
- **互斥**：同一枚火箭同一时间只允许一个玩家控制，原控制者释放后才允许接管。

## 位置同步与插值

- 插值**平滑时长设有上下限**，平滑量与数据包间隔成比例 —— 避免高延迟链路上过度平滑造成的操作迟滞；
- **网络自适应**：按实测网络状况调整状态发送间隔；
- **服务端状态队列**：同一枚火箭的状态只保留最新一条，慢客户端不会再积压过期状态。

## 玩家直连（P2P）

- 服务端按玩家位置与网络端点进行撮合，配对成功后玩家之间建立直连通道，直接在两者之间传输火箭状态，不再全程依赖服务端中转；
- 直连建立前先做**三次握手**确认，并通过过渡缓冲平滑切换，避免切换瞬间出现位置跳变；
- 直连中断时自动**回退到服务端中转**，界面显示当前通道状态（P2P 直连 / 连接中 / 服务器中转）；
- 相关行为由服务端 P2P 配置段控制：开关、撮合距离、验证周期、对端超时、过渡缓冲时长、单组人数上限、单客户端直连数上限。

## 网络传输

- 同时使用 **TCP 与 UDP**：需要可靠送达的业务包与高频状态包**按类型分流**，UDP 不可用时使用 TCP 进行必要的状态同步；
- UDP 绑定带**固定间隔心跳重试**：绑定丢失后可自动恢复，不需要重连整条连接。

## 世界维护

- **太空垃圾自动清理**：失去控制且部件数低于阈值的碎片会被自动移除，阈值可在服务端配置。
